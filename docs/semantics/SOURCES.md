# Sources and assertion authority

Retrieved September 19, 2026. Source references are research inputs, never runtime
parsers, network dependencies, copied implementation code, or consensus voters.
No private design document or third-party capture is included in this slice.

## Modbus: normative source

MODBUS Application Protocol Specification V1.1b3, April 26, 2012:
<https://www.modbus.org/file/secure/modbusprotocolspecification.pdf>

Publisher index: <https://www.modbus.org/modbus-specifications>

Sections 6.1 and 6.2 define read-coil/discrete input packing and zero-fill of unused
high-order response bits. Sections 6.3–6.6 define the read/write register and
single-coil fields. Sections 6.11 and 6.12 define write-multiple shapes, limits,
packed-bit order and register byte order. The FC15/16 payload cases use their
worked example values; the MBAP wrappers and network captures are original test
constructions. The authoring review viewed the relevant PDF pages; no copy of
the copyrighted specification is redistributed.

FC15's unused request-bit wording is a recommendation and is not elevated to a
universal MUST. Register device maps and vendor semantics are not supplied by
this specification and are deliberately not inferred.

## DNP3: implementation-reference cross-check, not normative certification

DNP3 remains governed by IEEE 1815. This package does not include a reviewed,
licensed normative edition or claim that a third-party implementation defines it.

Step Function I/O's authored DNP3 1.6.0 API reference was used to cross-check
qualifier values and group/variation descriptions:

- <https://docs.stepfunc.io/dnp3/1.6.0/rust/dnp3/app/enum.QualifierCode.html>
- <https://docs.stepfunc.io/dnp3/1.6.0/rust/dnp3/app/enum.Variation.html>

No implementation was copied, ported, vendored, or linked. The explicit integer,
bit-packing and float-bit fixtures are project assertions requiring independent
normative review. They are not mislabeled as IEEE conformance-suite vectors.
Qualifier/group legality, more event groups, object authentication, and device
behavior remain outside this cut. The CRC check string `123456789 -> EA82` is an
independent known-answer check, not generated by the encoder under test.
